# Managed clipboard failure contract (#109)

Standard actions, Git permalink publication, collection Copy All, history selection and status widget clicks consume `CopyPublicationOutcome`. They report only `NotPublished(CLIPBOARD_FAILURE)` through the project light service `CopyFailureReporter`. Errors use the fixed `notification.clipboard.failed` message in all five bundles and `NotificationType.ERROR`, independently of `enableNotification`. No copied code, file path, remote, credential or raw exception message is passed into this boundary. The message does not promise that an OS write which threw could not have partially changed the clipboard.

`report(request: CopyResultRequest, outcome: CopyPublicationOutcome, isOwnerAlive: () -> Boolean = { true })` first checks project/owner lifetime and application request identity. `ClipboardRequestCoordinator.claimFailureReport(request)` atomically accepts only the current failed write which has not claimed an error. The claim is consumed before scheduling and before presentation, preventing duplicate callers, multiple reporter instances and notification reentrancy from reporting twice. No write, retry, replacement token, restoration or success effect is performed by reporting.

The queued task captures only the request, reporter and optional owner lifetime predicate. It does not capture the outcome or payload. Project services do not store request-specific predicates. It checks the same lifetime and request at dispatch and passes a guard into `CopySelectionNotifier`, which checks again after notification construction immediately before `notify(project)`. Production entry points, request acquisition and notification presentation run on EDT. Notification construction can initialize services, so its final check is necessary even after dispatch validation.

`recopy(content: String, isOwnerAlive: () -> Boolean = { true }): CopyPublicationOutcome` acquires exactly one application request and passes it to `ClipboardRequestCoordinator.recopy(request, content, isAlive)`. The returned outcome is reported against that original identity. Content equality is never used for ordering. Re-copy success remains clipboard-only; it does not call the publisher or analytics/history/gutter/review/status/success notification adapters. History lifetime is its project; closing its popup after selection does not invalidate the request. The widget factory passes its project into the widget, which clears that reference and its copied value at disposal. A queued widget error additionally checks widget lifetime.

The coordinator retains only scalar sequence and attempt/failure/claim flags. It never retains projects, editors, documents, copied data, reporter callbacks or exceptions. Starting any new request resets the scalar flags and permanently supersedes older requests, even if the new request is cancelled, fails, or its project closes. A reentrant newer request started inside an older throwing write cannot inherit the older failure flag. Platform and coroutine cancellation propagate without becoming clipboard errors; their token is still consumed and is never retried.

`STALE`, `DISPOSED`, `ALREADY_ATTEMPTED` and `Published(feedbackFailures)` are silent at this error boundary. Optional feedback failure remains successful copying and cannot trigger a retry. Collection input invalidation, overflow and other pre-write errors retain their existing command reporting. Git metadata and HEAD validation failures are separate pre-publication policies; callers must not map them to `CLIPBOARD_FAILURE` to reuse this reporter.

`CopyFailureReporterTest` verifies claim state, repeated and reentrant reporting, cancellation, final guards and coordinator retention. `CopyResultPublisherTest` verifies each publication policy's failed-write/no-retry behavior. `ClipboardFailureFixtureTest` drives actual standard/Git actions, no-editor Copy All, the history popup's chosen callback and widget mouse listener with real project/editor owners. It controls dispatch and injects exceptions before clipboard writing, covering notification preference, cross-project ordering, identical-content ABA, failed/cancelled newer requests, disposal and optional feedback failure. These are deterministic injected failures, not a claim to have reproduced an OS clipboard outage or rendered a balloon in an interactive IDE.
